# Domain docs

This repo uses a single-context layout.

## Before exploring

Read root `CONTEXT.md` and relevant decisions in `docs/adr/`.

If they do not exist, proceed silently. Domain modeling creates them when terminology or architectural decisions are resolved; do not create empty documents just to satisfy this layout.

## Vocabulary and decisions

Use the glossary's terms in tickets, proposals, tests and explanations. If a needed concept is missing, reconsider the term or note the gap for domain modeling.

Flag conflicts with an existing ADR explicitly rather than silently overriding the decision.
